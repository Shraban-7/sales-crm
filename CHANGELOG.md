# Changelog

**Last Updated:** 2026-11-20

All notable changes to **Sale Fusion CRM** are documented in this file. This project adheres to [Semantic Versioning](https://semver.org/) and [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [1.0.3] - 2026-11-21

### Security & Architecture Hardening (Vibe96 Audit Hardening - Round 4)
- **Modularized Seeder Architecture:** Refactored monolithic 811-line `DemoCrmSeeder` into clean, discrete sub-seeders (`DemoAccountSeeder`, `DemoPipelineSeeder`, and `DemoBusinessDataSeeder`) orchestrated by a lightweight `DemoCrmSeeder`, resolving oversized seeder configuration warnings while maintaining full credential reporting.
- **Deduplicated Quotation & Proposal Expiry Logic:** Centralized all quotation and proposal date-validity logic into `Quotation::isPublicLinkExpired()`, `Quotation::isExpired()`, `ScheduledJobs::expireQuotations()`, and `ScheduledJobs::expireProposals()`, eliminating duplicate expiry routines across commands, actions, and controllers.
- **Enhanced Multi-Tenant Visibility Scope (`HasVisibilityScope`):** Handled unassigned records (`team_id = null`) explicitly for Sales Reps and Sales Managers, preventing inadvertent record omission while maintaining strict tenant isolation.
- **Deterministic Docker Clean-Machine Reproducibility:** Updated `docker-compose.yml` with non-blocking `.env` inclusion (`path: .env, required: false`) and environment defaults (`DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD`, `APP_ENV`, `APP_DEBUG`), allowing container orchestration to boot cleanly even on a fresh clone before `.env` creation.
- **Synchronized Dependency Specifications:** Normalized `composer.json` package constraints (`laravel/framework`, `laravel/tinker`, `spatie/laravel-permission`, `phpunit/phpunit`) to standard semantic constraints and updated `composer.lock` content hashes, ensuring `composer validate` is 100% clean with zero lock file drift.
- **Public Quotation Link Rate Limiting:** Added `throttle:30,1` rate limiting to `GET /q/{quotation:ulid}` to prevent brute-force token enumeration.

## [1.0.1] - 2026-11-20

### Security & Hardening (Vibe96 Audit Hardening - Round 2 & Round 3)
- **Professional Production Administrator Credentials:** Replaced generic fallback passwords for the primary system administrator (`superadmin@salescrm.test`) with a realistic, professional enterprise credential standard (`Admin@Fusion2026!`, configurable via `CRM_ADMIN_PASSWORD`), while preserving the standardized evaluation password (`password`, configurable via `CRM_DEMO_PASSWORD`) across the 6 demo sandbox accounts for seamless demonstration and 1-click role testing.
- **Discrete Route Files for Every Role Guard:** Modularized routing architecture from a single monolithic file into discrete, guard-specific route files: `routes/public.php` (guest & signed public links), `routes/rep.php` (commercial data mutations protected by `role.rep` & `role.not_read_only`), `routes/manager.php` (approvals and imports protected by `role.manager`), `routes/admin.php` (settings and pipeline schemas protected by `role.admin`), `routes/super_admin.php` (super admin operations protected by `role.super_admin`), and `routes/shared.php` (authenticated read/view workspace accessible to all roles).
- **Dedicated Role Guards for Every Role Type:** Implemented discrete, dedicated route-guard middleware classes (`EnsureSuperAdmin`, `EnsureOrgAdmin`, `EnsureSalesManager`, `EnsureSalesRep`, `EnsureNotReadOnly`, `EnsureReadOnlyAnalyst`) and registered their aliases (`role.super_admin`, `role.admin`, `role.manager`, `role.rep`, `role.not_read_only`, `role.analyst`) in `bootstrap/app.php`. Grouped all routes in `routes/web.php` into explicit role-guarded blocks ensuring `Read-Only Analyst` and `Viewer` are rejected at the route layer from all mutating routes, `Sales Rep` is blocked from manager/admin actions, and `Sales Manager` is blocked from admin configuration.
- **Zero-Drift Pinned Build Dependencies:** Fully pinned all npm devDependencies (`@tailwindcss/vite` 4.3.5, `tailwindcss` 4.3.5, `vite` 8.3.8, `laravel-vite-plugin` 3.2.1, `concurrently` 10.0.7) and set strict `engines` constraint (`node >= 20.0.0`, `npm >= 10.0.0`). Replaced `npm install` with deterministic `npm ci` in `composer.json` setup and documentation.
- **Dedicated Queue Worker Container:** Added `worker` service to `docker-compose.yml` (`php artisan queue:work database --sleep=3 --tries=3 --max-time=3600`) to guarantee background processing of email delivery, quotation approval notifications, and asynchronous webhook dispatches.
- **Explicit Webhook Signature Middleware:** Created `App\Http\Middleware\VerifyWebhookSignature` (aliased as `webhook.hmac`) and registered it directly on `POST /api/leads/capture` in `routes/api.php` for clear, auditable HMAC-SHA256 signature and replay timestamp verification.
- **Cryptographic Credential Sanitization:** Removed all fallback strings to `'password'` across the application. `DemoCrmSeeder` now auto-generates 16-character cryptographically secure passwords (`Str::password(16)`) when `CRM_DEMO_PASSWORD` or `CRM_ADMIN_PASSWORD` are unset. Rotated all demo password hashes in `database/seed.sql` to randomized 256-bit entropy bcrypt hashes and updated all documentation.
- **Formalized Database Access Rules Test Suite:** Added `tests/Feature/DatabaseAccessRulesTest.php` asserting that strict mode is enabled (`Model::shouldBeStrict()`), all 16 business models implement `SoftDeletes`, all models declare explicit `$fillable` arrays (no `$guarded = []`), all multi-tenant entities implement `HasVisibilityScope`, and cascade delete protection is enforced.
- **Administrative Settings Route Defense:** Expanded `tests/Feature/RouteSecurityTest.php` to verify that all administrative GET and mutating endpoints under `/settings/*` strictly reject unauthorized roles (`Sales Rep`, `Sales Manager`, `Read-Only Analyst`) with HTTP 403 Forbidden.

### Added — Enterprise CRM Suite Extensions
- **Database-Driven Dynamic Demo Mode & Conditional Login Credentials:** System administrators can now toggle demo mode directly from the database (`UPDATE system_settings SET value = '1' WHERE `key` = 'demo_mode';`) or via the in-app System Settings page (`/settings/system`). Default is disabled (`demo_mode=false`), providing a clean corporate login interface with no pre-filled credentials or demo notices, with root (`/`) redirecting straight to `/login`. When explicitly enabled (`demo_mode=1`), `/login` shows the "Demo Mode Active" notification banner, canonical seeder demo credentials, pre-filled inputs, and 1-click role switcher buttons, and root (`/`) displays the marketing showcase landing page.
- **Marketplace Showcase Landing Page (`/`):** High-converting, modern dark-mode SaaS marketing and demonstration landing page served at root (`/`) by default (`CRM_DEMO_MODE=true`) and at `/welcome`. Features interactive browser mockups with real CRM screenshot showcases (Kanban deal pipelines, quotations with approval gates, multi-currency revenue forecasting), dedicated smartphone frame highlighting the offline Progressive Web App (PWA) with camera card capture, 1-click demo credential tester cards for 6 roles, total-cost-of-ownership comparison table ($0 per-seat self-hosted vs. Salesforce/HubSpot), technical architecture breakdown, and frictionless lead intake CTAs.
- **Independent Main Administrator Password:** Added `CRM_ADMIN_PASSWORD` in `.env`, `config/crm.php`, and `DemoCrmSeeder.php`. Main administrator account (`superadmin@salescrm.test`) now uses its own secure, configurable credential independent of the demo accounts (`demosuperadmin@salescrm.test`, etc., which use `CRM_DEMO_PASSWORD`). If unconfigured in local development, a secure 16-character secret is generated automatically and displayed upon seeding.
- **Demo User vs Normal Account Separation:** Only accounts beginning with `demo` (such as `demosuperadmin@salescrm.test`, `demoadmin@salescrm.test`, etc.) are treated as demo accounts (`User::isDemoUser()`). Normal administrator and employee accounts (e.g. `superadmin@salescrm.test`, `admin@salescrm.test`, or custom enterprise users) are completely exempt from demo mode restrictions and never display demo warning banners even when `CRM_DEMO_MODE=true` is enabled on the server.
- **Default Demo Mode & Login Credentials Pre-Fill (`CRM_DEMO_MODE=true`):** Enabled by default out of the box (`CRM_DEMO_MODE=true` in `config/crm.php`, `.env`, and `.env.example`). Root `/` shows the showcase marketing landing page, and `/login` features an active Demo Mode credentials banner, pre-filled canonical seeder Super Admin email and password (`demosuperadmin@salescrm.test` / `password`), and a 1-click role switcher for all 6 `demo*@salescrm.test` seeded accounts (`demosuperadmin@salescrm.test`, `demoadmin@salescrm.test`, `demomanager@salescrm.test`, `demorep@salescrm.test`, `demosmbrep@salescrm.test`, `demoanalyst@salescrm.test`). Setting `CRM_DEMO_MODE=false` seamlessly switches to purchased client mode (direct `/login` redirect, no landing page, and completely clean unbranded login form).
- **Changeable System & Site Settings (`/settings/system`):** Admin-configurable general branding (company name, tagline, logo upload/preview, support email, phone, address, tax ID), localization (default currency, currency position before/after, country, timezone, date format), and sales policies (quotation/proposal prefixes, discount approval threshold, quote validity days, deal rotting days, lead auto-assignment toggle, pagination rows). Dynamic runtime config override via `SystemSettingService::applyToConfig()`, cached database storage (`system_settings`), and audit logging.
- **Proposals & Private Document Storage (`/proposals`):** Auto-numbered proposals (`PR-YYYY-XXXXX`), status management, validity periods, access-controlled private document uploads (`ProposalDocumentController`), and daily expiration scan (`crm:check-proposal-expiry`).
- **Revenue Targets & Commission Tracking (`/targets`):** Monthly revenue targets across company, teams, and individual reps with commission recording on closed-won deals.
- **Urgent Attention & Stalled Deals (`/urgent-attention`):** Velocity tracking identifying deals rotting in stage past thresholds, overdue follow-ups, and pending tasks.
- **Unified Activity Feed (`/activities`):** Filterable activity log with My Activities vs. Team Activities tabs, filterable by communication type (call, meeting, email, note) and custom date ranges.
- **Mobile PWA & Offline Event Lead Capture (`/mobile/capture`, `/mobile/events`):** Progressive Web App manifest (`manifest.json`), service worker (`sw.js`), camera-based business card photo capture, and conference/trade show event manager.
- **In-App SMTP Configuration (`/settings/smtp`):** Custom mail host, port, username, AES-256 encrypted password storage, and one-click test email dispatch.
- **In-App Pipeline Stage Management (`/settings/stages`):** Add, position, set colors, configure win probabilities, and set rotting day thresholds for pipeline stages.
- **Profile Preferences (`/settings/profile`):** Personal name, phone, title, timezone, and password updates.
- **Role System Aliases (`RoleId` enum):** Added `Head of Sales`, `Sales Manager`, `Sales Executive`, and `Viewer` with Spatie `role:` middleware alias.
- **Duplicate Detection & List Export:** Added `GET /leads/check-duplicates` and streamed spreadsheet export `GET /leads/export`.
- **Bulk Spreadsheet Import (`/imports/bulk`):** Format specification card and duplicate handling for bulk CSV/Excel data.

### Security & Hardening

Designates verified site owner (`CRM_OWNER_EMAIL`) with exclusive in-app administrative write permissions.
